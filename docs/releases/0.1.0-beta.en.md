# Yuzu NTFS 0.1.0 Beta (build 2)

A free, GPL-2.0-only NTFS filesystem extension and menu-bar app for Apple silicon Macs running macOS 26 or newer. No macFUSE, kernel extension, reduced security or reboot is required. English and Vietnamese follow your system language.

## Start safely

Install the notarized DMG into Applications. On first run, accept the beta backup notice and click **Enable Yuzu NTFS** with all FSKit drives ejected. This merges only Yuzu's identifier into the current user's FSKit settings, saves a timestamped backup and refreshes only that user's agent. The extension remains sandboxed; the host app is not sandboxed because system enablement needs that access. Apple's internal enablement preference may change in an OS update; **Open System Settings** is also available.

Every drive starts read-only. **Allow writing (beta)** remembers the NTFS serial and unmounts/remounts that volume. Writing requires all three: backup acknowledgement, the drive's allowlist entry and a clean safety probe. Turning the toggle off remounts read-only. Busy volumes are never force-unmounted. A failed remount leaves the preference saved for the next mount; close files and eject/reconnect.

The menu shows drives, size/free space, RW/RO badges, reasons and Windows-side instructions, Open and Eject. **Disable Yuzu NTFS** is the kill switch after all FSKit drives are ejected. Quitting alone does not disable the extension. Export diagnostics produces a ZIP only at your request; there is no telemetry.

## Known limits — read before writing

- **Keep a backup of anything you cannot replace.** This is experimental filesystem software, not a production-safety claim.
- Sparse files are read-only. Compressed and EFS-encrypted file contents are not writable; encrypted content cannot be read. BitLocker volumes cannot be mounted or decrypted.
- Hibernated, Fast Startup, dirty-log, dirty-flag and unsupported NTFS volumes cannot be made writable. Yuzu never deletes hibernation files or repairs/clears unsafe state. Shut down Windows fully or run Windows `chkdsk /f` as instructed.
- **M-R1:** after an engine error, new allocation, size/VDL and metadata changes stop, but kernel-retained mappings can still write already-mapped, already-allocated data until eject. There is no cache-revocation guarantee in this beta.
- Resident files on writable mounts may be promoted to non-resident storage on their first data mapping. Existing P0 data-path safety restrictions remain in force.
- macOS 27 disposable-VM testing is not physical-drive or Windows certification. macOS 26, physical SSD medians/surprise-removal and Windows `chkdsk` acceptance remain pending owner validation.
- Apple silicon only; macOS 26+. No disk formatting, repair, journal replay, BitLocker or Intel support.
- **No auto-update yet.** Eject FSKit drives, quit, replace the app in Applications with a newer signed download, reopen and check enablement. Sparkle is deferred.

Report problems with the [GitHub issue forms](https://github.com/bluecoral-vn/yuzu-ntfs/issues/new/choose). For suspected data loss, stop writing and choose the Data safety form. Review diagnostics before attaching them: logs can contain paths or drive details. Source and GPL license are in this repository.
