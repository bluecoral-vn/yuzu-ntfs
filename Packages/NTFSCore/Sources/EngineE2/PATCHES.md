# Engine E2 integration

Upstream files are pristine at the revision recorded in `upstream/README.md`.

- Relative `tt_*.c` symlinks compile the same core/ntfs, core/vfs, core/logfile, platform/src and pagecache/pagecache.c inputs as TT's top-level CMake build. Do not compile pagecache/standalone_shims.c: it duplicates the actual platform implementation.
- Package.swift supplies TT's include directories and GNU C assumptions (`-fno-strict-aliasing`, `-fwrapv`). `core/ntfs` is quote-only so its time.h cannot shadow system time.h. `-fno-modules` avoids the Linux-compat `struct rb_node` conflicting with Darwin's module definition under SwiftPM's Xcode build system. These are target-local flags, not changes to upstream headers.
- engine.c adapts positive-errno nb_blockdev callbacks to TT's negative-errno byte-count device API and attaches/detaches TT's required raw-device page cache. Device ownership stays with the caller.
- The bridge converts UTF-16/UTF-8 strictly without normalization, keeps case-sensitive lookup so the separate NFC/NFD fixture paths stay addressable, converts Unix timestamps to NTFS epoch/100 ns units, and translates attributes.
- TT's directory callback stops *before consuming* its current entry. The bridge consumes the callback entry and reports the next position (`current cookie + 1`); the 100,000-entry/1,000-entry-batch regression pins this distinction. Dot entries are omitted along with TT's default reserved-system-file filtering.
- TT's public API lacks physical extents, raw-I/O completion and a resident bit. internal.c confines private Linux-compat/runlist types to one translation unit. Under T5-R1, write mappings allocate clusters without pre-zeroing the payload or publishing EOF/VDL; completion updates exact byte sizes, not rounded allocation length. Under T5-R2, completion first zeroes any VDL-to-offset gap, preserving the newly written sector edges with raw read-modify-write, flushes payload/gap, then publishes sizes. Sparse holes remain holes. The upstream page-cache zero helper cannot be used after raw I/O: its zero-filled UNINIT cached page could overwrite the payload in the same page. Regression tests cover exact 1,000,003-byte EOF, failed completion, poisoned 3 MiB+5-byte gap plus 4097-byte payload, and cached-edge invalidation. Callers must serialize offloaded ranges with other inode mutations until completion, as documented in the ABI header.
- Named streams use mount-local high-bit reference IDs backed by TT's xattr API. These IDs are not persisted MFT references. The public TT API only exposes whole ADS values, so partial ADS reads currently require a temporary whole-stream buffer. Named-stream write/truncate/blockmap and symlink creation (no target parameter in nb_create) return ENOTSUP rather than silently operating on the unnamed stream.
- TT combines hibernation and Fast Startup into its hibernated result; E2 conservatively reports NB_HIBERNATED for both. It never discards a saved session or replays a journal. A read-write mount never requests read-only fallback.
- Upstream boundary bug found by `rejectsSignedOffsetOverflow`: passing UINT64_MAX to TT's nominally unsigned positional read becomes signed -1 internally; a resident read succeeded with a byte preceding its value. engine.c rejects offsets/ranges beyond INT64_MAX with EFBIG before entering TT, including wrapped writes and oversized truncates/maps. No upstream file is changed.
- Review fix round 1, T5-R3: when TT reports a newly allocated run materializing a sparse hole, zero its part below the preexisting initialized_size before returning a mapping (including payload bytes). Previously this ignored allocation result could expose recycled disk bytes around a partial-cluster write, or after mapping followed by failed/abandoned I/O. Beyond-VDL payloads remain unzeroed. The regression poisons every free cluster from the actual volume bitmap, exercises success and failure, and compares remounted bytes with ntfscat.
- Review fix round 1: raw mutation checks the inode's current core read-only/shutdown state before fsync/allocation/completion, and rechecks under the inode lock before mutation. The adapter's original device read_only flag is not authoritative after errors=remount-ro. A real injected MFT read fault on bigdir causes TT's normal remount-ro transition; the regression checks EROFS for both raw operations and no further block-device write callbacks.
- Review fix round 2: materialized-hole zeroing now includes a device flush. If either operation fails, TT's hole-punch primitive restores the original run to LCN_HOLE, rewrites mapping pairs and releases the allocated clusters before blockmap returns the I/O error. TT's allocation API installs the run before it returns; its deferred-update option can still publish mapping pairs under low-space conditions, so the bridge explicitly rolls back instead of treating that option as an atomic unpublished allocation. If rollback itself fails, mark the volume errored and use ntfs_error/errors=remount-ro, returning EIO. The new one-shot device-write-fault regression checks NB_EXT_HOLE immediately after the failure, zeros in buffered and remounted/external reads, and a successful retry without stale cluster edges.
- Task 7 ruling T7-R2 appends getattr, remove (file/empty directory), statfs, size/timestamp setattr and POSIX rename to the engine vtable without changing existing signatures. FSKit needs these for stat, cp/Finder attribute preservation and rm. Mutations check the current core read-only state. TT's size setattr overrides a supplied mtime, so the adapter applies size first and requested timestamps second. A temporary-image conformance test verifies statfs, ENOTEMPTY, exact size/zero growth, timestamp and rename persistence after remount, removal persistence after another remount, and EROFS mutations on a read-only remount.
- T7-R3/R4 amends the original resident ENOTSUP policy above: new regular files start nonresident; the first blockmap on a RW mount promotes an existing resident uncompressed/unencrypted file before mapping, whether the request is a read or write. A RO resident mapping still returns ENOTSUP for byte-copy fallback. The change addresses the observed macOS 27 inhibited-resident streaming-write wedge (kernel state-U, extension idle/no data upcalls). Lookup/getattr never promotes. Tests verify new files, writes after truncate-to-zero, and resident read mapping plus append retain exact persisted payload/EOF. This engine-level fix is green; its mounted FSKit behavior awaits the owner reboot described in `docs/spikes/p0-r3-throughput.md`.
- Task 7 review fix: append-only `nb_hold`/`nb_release` retain a counted core inode reference until FSKit reclaim (or volume teardown), so unlink/rename replacement cannot recycle an MFT record or its clusters while its FSItem remains live. TT's public `ntfs_inode_get` deliberately rejects nlink==0; ref-based data/attribute/map/completion operations therefore resolve a held inode and take a temporary `ntfs_inode_ref` before falling back to ordinary lookup. No upstream changes. A real-image Swift glue regression replaces a pinned file, attempts 32 MFT allocations, checks its retained identity/size, then observes free clusters increase only when the identity table reclaims/releases its pin; a separate pinned unlink is also exercised.
- Task 7 review fix: the Swift mapper treats ENOBUFS plus a nonempty prefix as partial progress, streams 128-entry stack-buffer batches to the FSKit packer and continues at the last extent's end. A real bridge-created file interleaved with 140 allocated blocker files exercises more than 128 physical extents without a mocked map.

## Final review safety cutover (F-R1/F-R2)

- `tt_core_ntfs_attrib.c` and `tt_core_ntfs_super.c` are now integration wrappers that include the pristine upstream translation units, not symlinks. No upstream source is edited.
- F-R1 supersedes the earlier sparse-materialization write policy: already-sparse files are readable but buffered/KOIO writes, size changes and write completions return EPERM. FSKit inhibits KOIO and rejects write-open for these files, as for compressed data. `e2_prepare` independently guards the old materialization path. P1: allocate detached clusters through TT lcnalloc, zero + flush them, then insert the runlist/update mapping pairs. A writer gate or `update_mp=false` alone is not a safe substitute. E8's secondary initialization/rollback fault is unreachable through the P0 ABI; the sparse-fixture test hook only creates on-disk fixture state and cannot bypass write authorization.
- F-R2: growth of ordinary files uses TT's private nonresident expansion primitive with HOLES_NO. Mapping passes the unchanged EOF plus a preallocation size, removing the fallible size-restoration phase entirely (E7). Explicit truncate/setattr growth allocates real clusters and changes EOF while preserving VDL. The completion gap-zero path therefore encounters allocated runs on these files, not newly published below-VDL sparse mappings.
- The super wrapper substitutes the free-space work callback. A failed readahead allocation now leaves a terminal negative free-count, sets errors/read-only, marks initialization known and wakes waiters. Mount joins this work and returns ENOMEM before exposing a volume to statfs or allocation. The fixture hook faults the actual file_ra_state kzalloc.
- Reserved records (<24) and direct $Extend children are diagnostic-read-only, marked NB_READ_ONLY and rejected at every user mutation boundary; root remains a valid namespace parent. Named streams retain their base inode through hold/release/getattr and carry NB_READ_ONLY for buffered reads; ADS mutations remain unsupported.
- Failed raw-write completions invalidate the affected cache before preserving the original I/O error; failed completions never advance sizes. Create rolls back its entry when promotion or initial getattr fails; failed rollback forces read-only/EIO.
- Append-only nb_dispose drains device callbacks and prohibits further resource I/O before releasing core ownership. It intentionally discards unsynchronized cached state for activation cancellation/deactivate and is not a durability operation. Ordinary mounted teardown still uses sync/unmount. Core diagnostics from refused teardown writeback remain visible.
- Swift uses current nb_statfs state to latch read-only routing, retains legacy-reclaim identities/pins until deinit, and rolls back failed initial-attribute creation with verifier invalidation.

## Targeted re-review FR-1

- Ordinary buffered growth now preallocates with the same HOLES_NO/unchanged-EOF primitive before entering TT's buffered writer. A write at 1 MiB cannot create sparse gap runs and thereby lock its next write out under F-R1. The writer still owns EOF/VDL advancement and zeroes the allocated gap.
- Successful size-only growth restores normal inode bookkeeping: mtime/ctime update, filename-dirty state and inode dirtying accompany the changed data size. Explicit user timestamps remain applied after size by the existing adapter.
- Swift holds the item I/O lock and volume serialization lock continuously across reading EOF, classifying an actual shrink, checking explicit extent overlap, applying size and producing final attributes. The former pre-lock grow/shrink snapshot was racy. Namespace remove/replace remains independent of mapping leases.
- Swift boundary helpers validate 64-bit resource geometry before allocation/narrowing, map unrepresentable NSError codes to EIO, and check reference IDs, enumeration cookies and signed mapping offsets. Device cache purge uses checked physical endpoints. The filesystem source is now also compiled by the headless FSKitGlue target.
- Benchmark supervision blocks termination signals across fork/setup, holds the worker behind a go-pipe, and grants serial authorization only in the supervising parent. Every post-fork parent failure revokes before attempting SIGTERM of its owned worker group; signaling denial is reported with the PID/group rather than causing unbounded cleanup or allowing worker reauthorization.

## Pre-deploy QC

- A2/A3: kernel-visible extent splits are device-block aligned rather than byte-VDL aligned. Write maps do not split DATA/UNINIT; read maps on RW cores zero and flush the partial VDL block before rounding the data/zero boundary. Completion zeroes its partial-block remainder before publishing exact VDL. RO files with partial VDL below EOF are marked NB_UNALIGNED_VDL and inhibited at publication; maps fail ENOTSUP without writes. Page-rounded read requests beyond allocation receive zero/hole extents. No upstream source or bridge struct layout changes.
- Q-R1/Q-R2: a published item's KOIO inhibition is immutable. The effective-RO latch rejects buffered writes and write blockmap/completion with EROFS; it does not revoke retained physical mappings. The P0-only Application Support/YuzuNTFS/p0-force-ro container file latches RO on the next operation; removing it does not unlatch the volume. Remove this hook in P1.
- B7 known dormant upstream compressed-write defects: `tt_core_ntfs_compress.c:1551` narrows a 64-bit compression-block offset into signed `int cb_off` (offsets >=2 GiB can wrap); line 1644 narrows `size_t written` through an `int` return (counts >INT_MAX cannot be represented). P0 rejects compressed write-open, buffered writes and KOIO mutation, so these write defects are unreachable through its permitted module path. Recorded, not fixed; upstream remains pristine.

## QC re-review round 1

- Completion cache purges use append-only `nb_query_extents`, not `nb_blockmap(for_write=0)`. A read map can pad a partial VDL block and is never a valid way to discover already-landed cached-write extents. The query returns physical DATA regardless of VDL, holes for unallocated tails, and bounded ENOBUFS prefixes without fsync, promotion, allocation, zeroing, flush or size changes. Resident/ADS/compressed/encrypted mappings stay unsupported. This preserves the 37–511-byte payload reported by an untracked write completion and makes untracked read completion non-mutating after the effective-RO latch. T7-R5 remains open for other, not-yet-reported writes.
- Reusable benchmark supervision restores signal handlers and the caller's mask after revoke-before-signal cleanup, so sequential guest phases and logger subprocesses do not inherit blocked termination signals.
- Installer isolation archives/verifies/removes unpacked known duplicate Yuzu bundles (including staging only after installed identity/hash/signature checks), then repeats inventory before final registration. Scope is worktree or `/tmp/yuzu-qc*`, with bundle-ID validation; other paths are listed and refused before changes.
- Additional verification fix authorized by Main: the terminal free-space producer publishes its original initialization error into bridge-owned atomic state before setting the core errors/RO flags. If TT's post-load reason ladder observes the failure early, the bridge preserves that cause rather than returning its generic EROFS; if it happens later, the existing worker join/negative-free-count path reports the same cause before publication. The ENOMEM/nil-volume/deadline regression remains unchanged and passed 20 consecutive ASan iterations. Upstream and the public ABI are untouched by this error-propagation correction.
- Read-lease review R-R1: an outstanding explicit write lease now selects append-only `nb_read_map_during_write` under the same item lock that creates/completes the lease. This route never fsyncs, promotes, allocates, pads or flushes: DATA runs end at the device-block-rounded VDL, with UNINIT beyond. An interleaved read (including a disjoint read at 4096) cannot zero bytes 37–511 that have landed before write completion. Without a lease the original read-map zero/flush remains necessary to avoid exposing stale bytes in a Windows-written partial-VDL sector; RO partial VDL still returns ENOTSUP and is inhibited. A2 alignment and write-completion tail padding remain unchanged.

## Performance pass (2026-10-25)

- `BridgePerf` is a headless real-bridge driver with `os_signpost` intervals and per-phase callback counters. It clones the supplied regular fixture before RW I/O, measures mount, 64 × 1 MiB map/raw-write/completion, 256 × create/4 KiB write/hold-release, and a 100000-entry attribute enumeration. These image/POSIX callback timings are not mounted FSKit or physical-device results.
- Contiguous growth at/above 1 MiB reserves to the next 8 MiB boundary (including small kernel upcalls), without changing EOF/VDL or pre-zeroing payload. ENOSPC on the speculative reservation retries exact requested allocation. Tiny files and gap writes retain exact allocation; F-R1 sparse and reserved-file restrictions are unchanged.
- Ordinary blockmaps drain dirty buffered file data with `filemap_write_and_wait`, rather than flushing the entire inode/device unconditionally. Resident promotion retains its explicit inode sync. Completion retains the payload/gap/tail device flush before VDL publication, invalidations and exact-byte sizes, but no longer synchronously checkpoints the inode and entire volume. The mounted adapter serializes a five-second D13 checkpoint with all callbacks; explicit synchronize and unmount still checkpoint. Timer failure latches the existing read-only gate; teardown cancels it.
- Mount no longer joins the bitmap producer. Bridge statfs returns a conservative zero-free estimate while unknown, then the actual count. All allocating/freeing user mutations pass readiness before entering TT's unbounded waits: a finite 1000 × 1 ms grace returns EAGAIN if initialization remains pending. Failed producers still publish their original terminal error, set RO/known and wake waiters; late statfs and mutations report that error. This supersedes the earlier mount-join note, not the terminal-error guarantee.
- Readdir resolves each inode once for both public attributes and private routing flags, rather than TT's attribute iget followed by another bridge iget. The Swift enumeration uses one effective-writability snapshot per serialized batch instead of a fault-hook path lookup/statfs per child. Published inhibition, cookies, exact sector-covering KOIO mappings, R-R1 outstanding-write rules and M-R1 retained-map behavior are unchanged.
- Metadata purge now probes the smaller of the cached-sector set and the mapped sector span, deduplicating physical sectors. Small-file maps/completions no longer walk the entire growing volume metadata cache. Flush-before-purge, partial-sector overlap, holes, large-extent fallback and the two completion purge boundaries are preserved.
- A post-checkpoint write re-arms and writes the volume dirty-marker record before publishing file metadata; its record is included in the existing payload durability flush. This also covers kernel-retained mappings with no new blockmap. Pending marker writeback is retried before mutation, and TT's suppressed-ENOMEM/redirty result is not accepted as marker persistence. A discard-without-sync regression verifies the actual detached dirty flag with and without a fresh mapping after a clean checkpoint.
